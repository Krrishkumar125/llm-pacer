Install

npm install llm-pacer ioredis   # or node-redis: npm install llm-pacer redis

Node 20+. No runtime dependencies. Bring your own Redis client (ioredis ≥ 5 or node-redis ≥ 4). Without a client the budget lives in process memory, which is handy for tests and one-off scripts.

pacer.acquire({ tokens?, maxWaitMs?, signal? })

Waits until the call fits every limit, reserves it and returns a Lease. tokens is your estimate for prompt plus maximum output.

pacer.tryAcquire({ tokens? })

One attempt with no waiting. It returns { ok: true, lease } or { ok: false, retryAfterMs, reason }, where reason is one of rpm, tpm, rpd, concurrency or penalty (paused after a 429).

Lease

  • settle(actualTokens?): the call finished. It refunds the unused part of the estimate, or charges the extra. Called without a number, it keeps the estimate.
  • release(): the call failed after it reached the provider. It frees the concurrency slot and keeps the estimate charged.
  • cancel(): the call was never sent. It refunds the request and its tokens.

All three are idempotent. If you never call any of them, the concurrency slot is freed after leaseTtlMs.

pacer.run(fn, options)

Runs acquire → fn() → settle. Options: everything from acquire, plus

  • usage(result) returns the real token count, used to settle.
  • headers(result) returns response headers, passed to observe().
  • retries (default 0) is how many times to retry after a rate limit or overload error. Each retry waits for the budget again.

When fn throws a rate-limit or overload error, the whole budget pauses for the provider's retry-after (or an exponential fallback of 1 s, 2 s, 4 s…). An exhausted quota and all other errors are rethrown right away.

observe / pause / status / reset

  • observe(headers) reads x-ratelimit-remaining-requests|tokens and anthropic-ratelimit-requests|tokens-remaining. It lowers the local budget if the provider reports less, and never raises it.
  • pause(ms) pauses every caller of this budget.
  • status() returns { requestsLeft, tokensLeft, dailyLeft, inflight, pausedForMs }.
  • reset() clears all state, so the budget is full again.

Errors

  • PacerTimeoutError (code: 'PACER_TIMEOUT', retryAfterMs, reason): no room within maxWaitMs.
  • PacerRequestTooLargeError: tokens is larger than the whole tpm, so the call can never fit.
  • PacerAbortError: the AbortSignal fired.

BullMQ

const worker = new Worker('llm', async (job) => {
  const lease = await paceJob(pacer, worker, { tokens: job.data.tokens }, Worker.RateLimitError);
  try {
    const out = await callModel(job.data);
    await lease.settle(out.usage.total_tokens);
    return out;
  } catch (err) { await lease.release(); throw err; }
}, { connection, concurrency: 16 });

If the budget is full, paceJob calls worker.rateLimit(wait) and throws BullMQ's RateLimitError. The job goes back to waiting without using an attempt.

Recipes

  • Per-tenant fairness: acquire from openai:gpt-4o-mini:tenant-42 first, then from the shared openai:gpt-4o-mini. Cancel the first lease if the second one times out.
  • Per-second limits (some providers and free tiers): set windowMs: 1000 and use a separate pacer with rpd for the daily cap.
  • Streaming: acquire before you open the stream and settle with the usage from the final chunk.
  • Tests: leave out redis to use the in-memory store, or pass new MemoryStore(() => fakeNow) to control the clock.

Internals

Each limit is a token bucket that refills continuously at limit / window. Every operation (acquire, settle, observe, pause, peek, reset) is one EVALSHA of the same Lua script, with a fallback to EVAL after NOSCRIPT. The time comes from the Redis TIME command. On acquire the script refills all buckets, drops expired leases, works out the wait for each limit, and deducts only if every wait is zero. A budget uses llm-pacer:{name}:s (hash: levels, timestamp, pause) and llm-pacer:{name}:l (sorted set of leases). Both keys have a TTL. The {name} hash tag keeps them in one Cluster slot. The full script is exported as PACER_LUA.

Caveats

  • Estimates are estimates. A long answer can push the token bucket below zero, and later calls then wait for it to refill.
  • Providers count in their own way (OpenAI also counts max_tokens toward TPM). Leave some headroom.
  • The memory store does not coordinate across processes.
  • If Redis is down, calls to the pacer reject with the Redis error. Decide in your own code whether to fail open or closed.
