Stop your workers from fighting over the same rate limit.

Every worker that calls an LLM API draws from one shared budget in Redis: requests per minute, tokens per minute and calls in flight, all checked in one atomic step. Calls wait their turn instead of collecting 429s.

npm install llm-pacer ioredis Quickstart View source 
const pacer = createPacer({
  name: 'openai:gpt-4o-mini',            // same name = same budget, everywhere
  redis,
  limits: { rpm: 500, tpm: 200_000, concurrency: 20 },
});

const reply = await pacer.run(() => openai.chat.completions.create(req), {
  tokens: estimateTokens(req.messages, { maxOutputTokens: 300 }),
  usage: (r) => r.usage?.total_tokens,             // refund what wasn't used
  retries: 3,
});

The problem

Provider limits apply to your API key. Your code runs in many processes.

Every worker counts on its own

Six workers that each allow the full limit send up to six times the limit together. The provider answers with 429s, every worker backs off on its own, and they all come back at the same moment.

Tokens are not requests

One call costs 200 tokens, the next costs 20,000, and you only learn the real number when the answer comes back. A plain request counter can't keep up with a tokens-per-minute limit.

Not every 429 is the same

"Slow down" and "your credits are used up" both arrive as HTTP 429. Retrying the second one wastes minutes and hides the real problem.

The usual tools stop short

bottleneck has had no release since August 2019. BullMQ's limiter counts jobs, not tokens. HTTP rate limiters are built to reject incoming traffic, not to pace your outgoing calls.

What you get

Small, one job, no runtime dependencies.

RPM + TPM + RPD + concurrency

All limits are checked and reserved together in one Lua script. A call that's short on tokens doesn't use up a request slot.

Reserve, then settle

Reserve the estimate before the call. settle(realTokens) refunds the rest, or charges the extra when an answer runs long.

Shared across machines

Any number of processes, containers or servers share one budget. It runs on the Redis server clock, so clock skew doesn't matter.

Waits, with jitter

acquire() sleeps exactly as long as the budget needs to refill, adds jitter so waiters don't wake together, and supports maxWaitMs and AbortSignal.

One 429 pauses everyone

When the provider sends retry-after, the whole budget pauses, so other workers stop too instead of piling on.

Rate limit vs. empty quota

classifyLlmError() separates rate_limit, quota_exhausted, overloaded and server. Quota errors are never retried.

Provider header sync

Reads x-ratelimit-* (OpenAI, Groq and other compatible APIs) and anthropic-ratelimit-*, and lowers the budget when the provider says less is left.

Crash-safe slots

A worker that dies mid-call can't hold a concurrency slot forever, because leases expire.

BullMQ-native

paceJob() sends jobs that don't fit back to the queue through worker.rateLimit(), without using up an attempt.

ioredis or node-redis

Tested with ioredis 5 and 6 and node-redis 4 and 6. Cluster-safe keys. The in-memory store needs no Redis, for tests.

Typed, ESM + CJS

Written in TypeScript, with the full API typed. Node 20+. MIT licensed.

Honest estimates

estimateTokens() is a rough chars/4 helper. Pass an exact count if you have a tokenizer. Settling corrects the budget either way.

Quickstart

  1. Install with your Redis client of choice.
    npm install llm-pacer ioredis    # or: npm install llm-pacer redis
  2. Create a budget with the limits from your provider dashboard (a little under them if you want headroom).
    import { Redis } from 'ioredis';
import { createPacer, estimateTokens } from 'llm-pacer';

const pacer = createPacer({
  name: 'anthropic:claude-sonnet',
  redis: new Redis(process.env.REDIS_URL),
  limits: { rpm: 50, tpm: 40_000 },
});
  3. Wrap the call. Every process that uses the same name now shares the budget.
    const msg = await pacer.run(() => anthropic.messages.create(req), {
  tokens: estimateTokens(req.messages, { maxOutputTokens: req.max_tokens }),
  usage: (m) => m.usage.input_tokens + m.usage.output_tokens,
  retries: 3,
});
  4. Using BullMQ? Pace inside the processor.
    const lease = await paceJob(pacer, worker, { tokens: job.data.tokens }, Worker.RateLimitError);

How it works

Each limit is a token bucket that refills continuously. Every operation is one EVALSHA of a single Lua script. It refills all buckets, checks every limit, and only deducts if every limit has room. Otherwise it returns the exact wait for the slowest limit. Concurrency is a sorted set of lease IDs scored by expiry. Each budget uses two keys with a TTL and a shared hash tag, so it works on Redis Cluster. Read the internals →
